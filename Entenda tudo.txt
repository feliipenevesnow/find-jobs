É possível eu juntar todas essas ferramentas em uma só minha?

Sim, é totalmente possível — e juntar o melhor dessas ferramentas em um sistema próprio traz dois ganhos diretos: você recebe alertas exatamente no seu perfil e ainda constrói um projeto real de engenharia de software para colocar no portfólio.

O segredo não é misturar o código inteiro de vários repositórios (o que gera conflito de dependências e manutenção pesada), mas montar um único pipeline modular onde cada ferramenta entra apenas como uma peça isolada.

Arquitetura do seu caçador unificado
Você pode estruturar o projeto em 5 camadas simples, mantendo tudo leve o suficiente para rodar de graça:

Coleta (Conectores independentes): Cada fonte vira um pequeno módulo que retorna vagas brutas:

LinkedIn e Indeed: biblioteca python-jobspy configurada para buscar apenas vagas publicadas nas últimas 2 horas.

Gupy: requisições HTTP diretas na API pública de busca de vagas da Gupy filtrando por termos como "Desenvolvedor Júnior" ou "Estágio".

GitHub Issues: chamadas à API oficial do GitHub para ler Issues recém-abertas nos repositórios de vagas da comunidade (backend-br/vagas, frontendbr/vagas, etc.).

Normalização e Deduplicação: Como cada portal entrega campos diferentes, uma camada tradutora converte tudo para o mesmo formato (titulo, empresa, link, descricao, fonte, data_publicacao). Um identificador único (hash gerado a partir de link limpo ou empresa + titulo) barra duplicatas quando a mesma vaga aparece no LinkedIn e na Gupy ao mesmo tempo.

Filtro inteligente (Regras + IA opcional):

Regras rígidas (Regex): descarta instantaneamente vagas com termos como "Pleno", "Sênior", "3+ anos" ou tecnologias fora do seu foco.

Score de aderência (opcional): apenas as vagas que passam pelo Regex vão para uma LLM leve (via API ou rodando localmente com Ollama) para comparar a descrição com o seu currículo e gerar uma nota de 0 a 10.

Armazenamento e Controle: Um banco enxuto (SQLite ou Supabase) guarda as vagas já processadas. Isso garante que o bot nunca repita alertas e permite rastrear o status de cada processo (nova, candidatado, entrevista, descartada).

Automação e Entrega:

Agendamento gratuito: um workflow do GitHub Actions (rodando via cron a cada 1 hora) ou um fluxo no n8n dispara a coleta automaticamente sem você precisar manter servidor ligado.

Alerta rápido: um bot no Telegram ou webhook no Discord avisa em segundos assim que surge uma vaga aprovada.

Painel web (opcional): um frontend leve (React/Vite) ligado a uma API (como FastAPI) ou direto ao banco transforma o histórico em um quadro Kanban de candidaturas.

Como construir sem perder foco na busca pelo emprego
O maior risco ao criar sua própria ferramenta é passar semanas polindo o código em vez de enviar currículos. Divida a construção em 3 versões rápidas:

Versão 1 (funcional em 1 dia): Script em Python com JobSpy + API da Gupy, filtro básico de palavras-chave, deduplicação em JSON ou SQLite e envio no Telegram rodando no GitHub Actions a cada hora. Já coloca você no topo da fila das vagas hoje.

Versão 2 (fim de semana): Adicione o conector de GitHub Issues, regras de Regex mais finas para bloquear falsas vagas júnior e uma nota automática de aderência ao seu currículo.

Versão 3 (diferencial de portfólio): Crie o painel web (Kanban + estatísticas das vagas coletadas) e publique o repositório bem documentado no seu GitHub — recrutadores valorizam muito quem automatiza a própria dor.

Atenção prática: Evite fazer scraping agressivo com intervalos curtos demais (como a cada 2 minutos) no LinkedIn para não tomar bloqueio de IP. Intervalos de 30 a 60 minutos são o ponto ideal entre rapidez e estabilidade.

# Arquitetura Obrigatória do Sistema (Pipeline em 5 Camadas)

Estruture o projeto em **Python 3.11+** com arquitetura modular:

### 1. Conectores de Coleta (`src/collectors/`)
Cada fonte deve implementar uma interface base (`BaseCollector`) e rodar isolada dentro de `try/except` com logs claros — se um portal bloquear ou cair, os demais precisam continuar funcionando normalmente:
- **LinkedIn e Indeed:** usar `python-jobspy` com filtro `hours_old`, país Brasil e busca pelos termos do `config.yaml`.
- **Gupy:** cliente HTTP assíncrono/resiliente (`httpx`) consultando os endpoints públicos de busca de vagas da Gupy por palavra-chave e filtrando por data de publicação recente.
- **GitHub Issues (Comunidade BR):** cliente usando a API oficial do GitHub (com suporte opcional a `GITHUB_TOKEN` para evitar rate limit) lendo Issues recém-abertas em repositórios configuráveis (ex.: `backend-br/vagas`, `frontendbr/vagas`, `react-brasil/vagas`, `pydevbr/vagas`).
- **Boas práticas de scraping:** User-Agent realista, timeouts definidos, retry com backoff exponencial e pausas curtas entre requisições para evitar bloqueio de IP.

### 2. Normalização e Deduplicação (`src/core/`)
- Modelo único de vaga usando **Pydantic** (`JobPosting`): `id_hash`, `title`, `company`, `location`, `is_remote`, `url`, `source`, `published_at`, `description`, `salary`, `status`.
- **Limpeza de URL:** remover parâmetros de rastreamento (`utm_*`, `refId`, etc.).
- **Deduplicação forte:** gerar hash determinístico (SHA-256) combinando `empresa normalizada + título normalizado` (ignorando acentos, pontuação e maiúsculas) e também checar URL canônica, evitando alertas repetidos quando a mesma vaga sai na Gupy e no LinkedIn.

### 3. Filtro Inteligente em Duas Camadas (`src/filters/`)
- **Camada 1 — Filtro Determinístico (Regex e Regras):** barato e instantâneo. Descarta vagas que contenham bloqueios no título ou exigência explícita de >= 3 anos de experiência na descrição, e atribui pontuação básica de palavras-chave da minha stack.
- **Camada 2 — Avaliador com IA (Opcional e Desacoplável):** apenas as vagas aprovadas na Camada 1 seguem para uma LLM configurável via `.env` (suporte nativo a **Gemini API**, **OpenAI/Groq** ou **Ollama local**).
  - Compara a descrição da vaga com o conteúdo de `curriculo.md`.
  - Protege contra *prompt injection* presente em textos externos de vagas.
  - Retorna JSON estrito validado via Pydantic contendo: `score` (0 a 10), `senioridade_real` (estagio/junior/pleno/senior/indefinido), `skills_match` (lista), `skills_faltantes` (lista), `red_flags` (lista) e `resumo_curto` (máx. 2 frases).
  - **Fallback obrigatório:** se a cota da API acabar ou a LLM falhar, o sistema NÃO pode travar; deve encaminhar a vaga aprovada pelo Regex com a tag `[Análise IA indisponível]`.
  - Só notificar vagas com `score >= MIN_SCORE` (padrão `6.5` no `config.yaml`).

### 4. Persistência e Controle de Candidaturas (`src/storage/`)
- Banco **SQLite** como padrão (usando padrão Repository para facilitar migração futura para Supabase/PostgreSQL).
- Tabelas para registrar todas as vagas vistas (evitando reenvios), notas da IA, data de coleta, data de notificação e status da candidatura (`nova`, `salva`, `candidatado`, `entrevista`, `descartada`).

### 5. Notificação e Automação Gratuita (`src/notifiers/` e `.github/workflows/`)
- **Telegram Bot:** mensagem formatada em HTML/Markdown limpo (escapando caracteres especiais para nunca quebrar o envio) contendo:
  - Nota de aderência (ex.: `⭐ 8.8/10`), título, empresa, modalidade e fonte;
  - Tempo desde a publicação;
  - Skills que batem e eventuais *red flags*;
  - Link direto clicável para candidatura.
- **GitHub Actions (`hunt.yml`):** workflow agendado via `cron` a cada 1 hora (e com `workflow_dispatch` para rodar manualmente), usando GitHub Secrets para chaves sensíveis e persistindo o banco SQLite atualizado de volta no repositório (commit automático com `[skip ci]`) ou conectando ao Supabase via variável de ambiente.
- **CLI útil (`main.py`):** suportar flags como `--dry-run` (executa tudo e imprime no terminal sem enviar no Telegram nem marcar como enviada), `--hours 24` e `--skip-ai`.
